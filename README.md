# 入れ方

1. このリポジトリの **Releases** を開き、最新の `aliexpress-coupon-grab-<タグ>.apk` をダウンロードします。
2. APK を開いてインストールします。必要なら、ダウンロードに使ったアプリの「不明なアプリのインストール」を許可します。
3. アプリの「実行に必要な設定」から、ユーザー補助の「アリエク券取り」を有効にします。
4. ユーザー補助の項目が灰色で選べない場合は、端末の「設定 → アプリ → アリエク券取り」の右上メニューなどから「制限付き設定を許可」を選び、もう一度有効にします。表示場所は端末によって異なります。
5. アプリへ戻り、「正確なアラーム」と「通知」の状態を確認し、許可を求められた項目を許可します。Android 13 以降の正確なアラームはアプリの宣言により許可されるため、手動設定が不要な場合があります。

## アリエク券取り

Android 12（API 31）以降向けの、AliExpress プロモコード自動適用アプリです。日本時間の秒指定と1〜60分の繰り返し（既定5分）に対応します。券を取る直前に毎回ネットの時計と比べ、スマホの時計のずれを自動で直した時刻で「適用」を押します（画面の「今すぐ測る」で今のずれも確かめられます）。**支払い・注文確定のボタンは押しません。** NAS がなくても単独で使えます。

### 更新するには

Releases から新しい APK を取得し、上書きインストールします。[Obtainium](https://github.com/ImranR98/Obtainium) にこのリポジトリの URL を登録すれば、GitHub Releases の APK を使った更新確認・更新もできます。更新後はユーザー補助などの設定が有効か確認してください。

上書き更新には、同じアプリID・同じ署名鍵と、前より大きい `versionCode` が必要です。別の鍵で署名された版（開発用の debug 版を含む）からは上書きできません。削除して入れ直す場合は保存済みの予定や履歴が失われます。

## ビルドと公開の準備

このフォルダ自体を、単独のリポジトリの最上位に置く構成です。親フォルダの設定やスクリプトには依存しません。JDK 21 と Android SDK Platform 37.0（パッケージ名 `platforms;android-37.0`）が必要です。Gradle は同梱の起動ファイル（Wrapper）で取得します。

SDK の指定名は、[Google公式の配布一覧](https://dl.google.com/android/repository/repository2-3.xml)と `sdkmanager --list --channel=0` で確認しています（2026-11-01）。どちらも `platforms;android-37.0` を掲載し、`platforms;android-37` は掲載していません。ローカルの配置先は `platforms/android-37.0`、`source.properties` の `AndroidVersion.ApiLevel` は `37.0` です。公開処理もこの正式なパッケージ名を指定します。

```sh
./gradlew testDebugUnitTest assembleDebug
./gradlew assembleRelease
```

debug 版は通常の開発用署名のままです。ローカルの release 版は、以下の環境変数がすべて空でない場合だけ署名します。1つでも未設定または空なら未署名です。未署名の APK はそのまま端末にインストールできません。

| 環境変数 | 内容 |
| --- | --- |
| `CG_KEYSTORE_FILE` | 既存の署名鍵ファイルのパス（絶対パス推奨） |
| `CG_KEYSTORE_PASSWORD` | 鍵ファイルのパスワード |
| `CG_KEY_ALIAS` | 鍵の別名 |
| `CG_KEY_PASSWORD` | 鍵のパスワード |

### GitHub Releases の署名設定

単独リポジトリの Actions 用の秘密情報（Repository secrets）に次を登録します。鍵やパスワードをリポジトリへ保存しないでください。`*.jks` と `*.keystore` は追跡対象から除外しています。

| Secret | 内容 |
| --- | --- |
| `KEYSTORE_BASE64` | 既存の署名鍵ファイルを Base64 にした内容 |
| `CG_KEYSTORE_PASSWORD` | 鍵ファイルのパスワード |
| `CG_KEY_ALIAS` | 鍵の別名 |
| `CG_KEY_PASSWORD` | 鍵のパスワード |

`v1.1` など `v` で始まるタグが送信されると、`.github/workflows/release.yml` がテストと release ビルドを行い、署名した `aliexpress-coupon-grab-<タグ>.apk` を Releases へ添付します。タグ名には英数字・ピリオド・下線・ハイフンだけを使います。タグ名はアプリのバージョンを自動変更しないため、公開前に `app/build.gradle.kts` の `versionCode` と `versionName` も更新します。現在は `2` / `1.1` です。

公開処理では4つの秘密情報を必須とし、不足があれば停止します。鍵ファイルは実行用の一時領域（`RUNNER_TEMP`）だけに復元し、成功・失敗時とも削除します。更新のたびに同じ署名鍵を使い、安全に保管してください。この手順は新しい鍵を作りません。

参照: [Android公式の署名手順](https://developer.android.com/studio/publish/app-signing)、[Gradle公式の実行準備](https://github.com/gradle/actions)、[Android SDKの実行準備](https://github.com/android-actions/setup-android)、[Releasesへの添付処理](https://github.com/softprops/action-gh-release)（指定の v2 を使用）。

## 実行と状態

- コードは 1 行に 1 つ、ASCII 英数字 3〜32 文字です。状態は「待ち・取れた・使用済み・失敗」です。
- 「予定を追加」または予定の「編集」で開く画面は、上部に「閉じる」「保存」があり、既存の予定では「削除」も表示します。「閉じる」は変更を保存せず戻ります。実行中は予定の追加・編集・保存・削除ができません。
- ユーザー補助は設定が有効かだけでなく、画面操作のサービスが実際につながっているかも確認し、「動いている」「設定は入っているが動いていない」「外れている」を表示します。未接続なら警告欄の「付け直す」から設定へ進めます。灰色で選べない場合のために「アプリ情報を開く」も用意しています。
- 時刻指定は券の取得時刻の10分前に接続を点検し、10分前を過ぎて登録した場合はその場で点検します。繰り返しは毎回の実行前に点検します。未接続の通知は、時刻指定では同じ実行回につき1度、繰り返しでは切れたままの間に1度です。接続の回復を確認した後に再び切れれば、繰り返しでも再通知します。通知済みの状態は保存し、アプリの処理が作り直されても同じ警告を重ねません。
- 1回の実行では登録順にコードを試し、「無効」は列の最後に戻して次のコードへ進みます。「取れた」「使用済み」は列から外します。最初に「適用」を押した時から、開始時の対象コード数×15秒を全コードで共有します。再試行で時間は増えず、時間切れで残ったコードは失敗になります。
- 前のコードの「無効」表示を読み違えないよう、表示が変わるか、「適用」を押してから1.2秒たつまでは無効と判定しません。適用の確認窓が出た場合は「承認」を1度押し、適用済みと読めるまで次のコードへ進みません。高い券が当たっている時に低い券を入れると、小窓が閉じてから確認窓が出るまでに一瞬「適用済み」に見える画面が挟まるため、適用済みの表示が1.5秒続いた時だけ取れたと判定します。
- 「適用」を押す間は2秒以上あけ、1回の実行で押すのは25回までです。押しすぎるとアリエクの安全確認（スライダー）が出るためです。安全確認が出たらその場で止め、すべての予定を休みにして、音つきの通知と最初の画面の赤い帯で知らせます。スライダーはアプリでは解きません。アリエクを開いて手で解き、帯の「再開」を押してください。休み中に来た予定は履歴に「安全確認のため予定を見送り」と残し、繰り返しは次の回へ送ります。
- 時刻指定では失敗も終端です。繰り返しでは待機と失敗だけを再試行し、適用済み・使用済みは再実行しません。全コードが終端になると予定を停止します。
- 時刻指定では 60 秒前に foreground service が起動し、カートとコード入力を準備します。繰り返しと NAS 延期は指定時刻ちょうどに起動します。補正した時刻の直前は単調時計で待機し、押す直前と直後の補正時刻を記録します。最後約20msまでは中断できる待機を使い、最後約20msだけ単調時計を読み続けます。
- 実行要求は ID ごとに保存して直列処理し、時刻指定を繰り返しより優先します。同じ時刻の時刻指定同士も順番に処理するため、完全な同時適用は保証しません。
- 時刻は複数 SNTP サンプルの最小 RTT を採用し、失敗時は HTTP Date へ切り替えます。両方とも失敗した場合は警告通知を出し、補正なしの端末時計を使います。
- 履歴はミリ秒 timestamp 付きで最新 100 件を保持します。予定・状態は、アプリ内 JSON ファイルへアトミックに保存します。

## NAS との調整

NAS 連携は任意です。`NasReceiver`（通知の受け口）と状態取得用の窓口（status provider）は、どちらも `android.permission.DUMP` で保護しています。通常のアプリはこの権限を持たないため呼び出せません。以下は、その権限を持つ `adb shell` から操作する例です。

端末側の `busy` は、時計測定・画面準備・適用・後片付けの間 `true` です。NAS 側の busy 状態とは別に保持します。

```sh
# NAS busy（untilMs は epoch ミリ秒）
adb shell am broadcast --user 0 -a com.tamacolet.coupongrab.NAS_BUSY -n com.tamacolet.coupongrab/.NasReceiver --el untilMs 1893456000000
# NAS free
adb shell am broadcast --user 0 -a com.tamacolet.coupongrab.NAS_FREE -n com.tamacolet.coupongrab/.NasReceiver
# 停止中のServiceでも取得できる、DUMP権限で保護した状態窓口
adb shell content call --user 0 --uri content://com.tamacolet.coupongrab.status --method status
```

出力は `coupongrab busy=true|false nextExactAtMs=epoch|0 nasBusyUntilMs=epoch|0` です。NAS busy 中の繰り返し予定は 30 秒ごとに延期し、NAS が空くまで延期を続けます。次の時刻指定まで3分以内の場合も繰り返しを30秒延期し、60秒前の準備を優先します。時刻指定は NAS busy より優先します。実行中は `adb shell dumpsys activity --user 0 service com.tamacolet.coupongrab/.GrabService` でも同じ行を返します。停止中は上の状態窓口を使います。

## 安全上の制約とフォールバック

**「今支払います」「注文」「支払」を含むボタン、および place order / pay now / payment 系 ID は絶対に押しません。** クリック対象の祖先と配下も検査し、危険なら処理を中止します。購入手続き画面の「プロモコード」行は押せる印（clickable）を持たないため、その文字の中心を位置で押します。位置で押す前に、その文字・祖先に加え、押す位置に重なる全ての部品（押せる部品は配下まで）を同じ禁止語で検査します。実際に押すのは、必要時のカートの全選択、「購入手続きへ」、「プロモコード」行、「適用」（再試行を含む）、「承認」、小窓を閉じるボタン、「中止する」です。これらは全て同じ PaymentSafety の検査を通します。画面を戻す操作、入力欄の選択と文字入力、行の表示・スクロールも行います。支払いは実行しません。

AliExpress の画面構造が変わった場合は失敗として終了します。画面は「今使っている窓」ではなく、重なり順で一番上のアプリの窓を読みます（「会計手続きを中止しますか」の窓はフォーカスを持たず、キーボードが出る瞬間は今使っている窓が取れないため）。無効と出たコードは「適用」が押せない状態になるので、押し直しの前に入力欄を空にしてから入れ直します。ロック画面の表示・キーガード解除を待ってからカートを開きますが、端末によっては認証や手動解除が必要です。AliExpress が前面にある間の画面維持には、20 分で必ず切れる従来型の画面 WakeLock を使います（Activity のフラグと PARTIAL_WAKE_LOCK だけでは維持できません）。正確なアラーム未許可時は不正確なアラームへフォールバックせず、設定画面で未許可を表示します。

画面操作で対応していること:

- 窓の控え（キャッシュ）が古いまま残り、消えた窓しか見えないことがあるので、読めない時は控えを消して（`clearCache()`）読み直します。
- 支払い方法の欄が長いと、プロモコード行が画面の下にはみ出して支払い欄と重なります。行を画面の中へ出し、位置が止まってから押します。
- 読み込み途中にプロモコード行を押すと、小窓ではなくウェブの「工事中」画面（`AEBuildingActivity`、promocode_v3.html）が開くことがあります。戻って最大3回押し直し、後片付けでもこの画面なら先に戻ります。
- 入力欄の×ボタンは押した後で遅れて効き、入れた文字まで消すので使いません。空にしてから入れます。
- 割引の大きい券を上書きする時は「このクーポン/コードを本当に適用してよろしいですか?」が出るので「承認」を押します（注文はしません）。
- 中断や時間切れでも後片付けを試みます。適用の確認窓が残っていれば「取り消し」を押し、コード入力の小窓を閉じてから会計を「中止する」で終了し、カートへ戻ります。後片付けは最長30秒で、失敗は履歴に残します。
- 失敗の後はキーボードが残り、「戻る」の1回目はキーボードを閉じるだけのことがあるので、後片付けでは「戻る」をカートに着くまで最大3回くり返します。


登録には省電力中にも起動できる `setAlarmClock` を使うため、端末に目覚ましの印が出ます。1回の実行は最長20分、5分以上遅れた予約は失敗で終了します。SNTPの名前解決は取り消せますが、HTTP側の端末標準の名前解決が停止すると計測の目安12秒を超える場合があります。
